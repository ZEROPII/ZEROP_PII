# MediCloak 운영 모드 (`python -m medicloak`)

의료진은 로그인해 가상 EMR의 내 담당 환자 목록에서 환자 차트를 보고, 필요하면 `.env`에 넣은 실제 LLM에게 비슷한 과거 사례를 묻습니다. 담당이 아닌 환자는 목록에 없습니다. 협진은 담당 의료진이 보낸 의뢰를 번호 없이 열고, 당직 · 응급처럼 꼭 봐야 할 때만 등록번호와 사유를 적고 엽니다. 환자를 열 때의 첫 답부터 실제 LLM이 씁니다. MediCloak은 그 답이 화면에 나가기 전에 대화 전체의 단서를 사례마다 모아 세고, 환자를 알아볼 수 있는 값은 넓히거나 가립니다. 보안 담당자는 다른 계정으로 로그인해 같은 대화를 숫자와 함께 보고, 의료진의 세부 정보 요청을 승인해 가린 값을 열어 주거나 대화에 규칙을 걸고, 레드팀 점검을 실제 LLM으로 돌립니다. EMR을 누가 열었는지 보고 담당 외 예외 열람을 검토합니다. 원문 열람 · 승인 · 규칙 · 예외 열람은 사유와 함께 감사 기록에 남습니다.

화면과 서버 코드는 데모(`python -m webdemo`)와 같습니다. 다른 점은 아래뿐입니다.

| | 데모 `python -m webdemo` | 운영 `python -m medicloak` |
| --- | --- | --- |
| 대상 AI | 결정적 응답기 (LLM 호출 없음) | `.env`의 실제 LLM: 첫 답(사례 검색)부터 모든 질문, 레드팀 점검까지 (기본). `--llm oracle` · `--llm dry-run`도 됨 |
| 로그인 | 없음 (화면 전환 단추) | 계정 · 역할. 의료진과 보안 담당자는 서로의 API를 못 씀 |
| 대화 | 화면 하나 = 대화 하나 | 의료진 계정마다 따로 |
| 환자 | 데모 환자 목록 (처음부터 기본 환자가 열림) | 가상 EMR 내 담당 환자 (DB · FHIR R4). 담당 환자만 열리고, 환자를 열기 전에는 대화가 없음 |
| 기록 | 메모리 (끄면 지워짐) | SQLite DB (다시 켜도 남음) |
| 의료진 화면 API의 위험 숫자 | 없음 | 없음 |
| 관제의 시뮬레이션 대화 | 켤 때 6개 만듦 | 없음 (실제 의료진 대화만) |
| 레드팀 · 리포트 | 결정적 응답기 | 실제 LLM, 규모를 골라 실행 · 멈춤 · DB에 남김 |

## 처음 실행

저장소 맨 위 폴더에서:

```bash
source venv/bin/activate                 # 없으면: python3 -m venv venv && source venv/bin/activate
pip install -r webdemo/requirements.txt
python -m medicloak init                 # DB · 가상 EMR(576명) · 처음 쓸 계정 3개 · 담당 배정. 비밀번호를 한 번 보여 주고 파일에도 적음
python -m medicloak check-llm            # .env를 읽어 실제 LLM에 짧은 요청을 한 번 (키 값은 출력하지 않음)
python -m medicloak serve --build        # 화면 빌드 후 서버. http://127.0.0.1:8000
```

`init`이 만든 계정과 비밀번호는 `runs/medicloak/initial_accounts.txt`(권한 600)에 있습니다. 예전 `init`으로 만들었다면 `demo_accounts.txt`입니다. `runs/`는 커밋하지 않습니다.

| 아이디 | 역할 | 이름 |
| --- | --- | --- |
| doctor1 | 의료진 | 김서연 (내과) |
| doctor2 | 의료진 | 박준호 (가정의학과) |
| privacy1 | 보안 담당자 | 이하늘 (개인정보보호팀) |

비밀번호를 정해서 만들려면 `python -m medicloak init --initial-password '원하는 비밀번호'`(셋이 같이 씀) 또는 환경변수 `MEDICLOAK_INITIAL_PASSWORD`. 이미 계정이 있으면 다시 만들지 않습니다.

### `.env`

저장소 맨 위의 `.env`(`.env.example`을 복사)에 넣습니다. 셸 환경변수가 있으면 그것이 우선합니다.

```
LLM_API_KEY=...
LLM_API_BASE=...
LLM_MODEL=...
# 선택: LLM_MAX_TOKENS · LLM_TIMEOUT_SEC · LLM_MAX_RETRIES · LLM_MIN_INTERVAL_SEC (분당 호출 제한이 있으면 간격을 줌)
```

`check-llm`이 `[설정 오류]`를 내면 빈 변수 이름을 알려 줍니다. `[호출 실패] LLMHTTPError: HTTP 401`이면 키, `404`면 주소나 모델 이름을 확인합니다.

## 서버 옵션

```bash
python -m medicloak serve [옵션]          # serve는 생략해도 됨
```

| 옵션 | 뜻 |
| --- | --- |
| `--llm real` | 의료진 대화의 대상 AI를 `.env`의 실제 모델로 (기본) |
| `--llm oracle` | 키 없이: 결정적 응답기 (데모와 같은 답) |
| `--llm dry-run` | 키 없이 배선만 확인: 가짜 LLM (답 내용에는 의미가 없음) |
| `--llm-concurrency 1` | 동시에 처리하는 질문의 LLM 요청 수 |
| `--extract-parallel 4` | 답에 사례가 여럿이면 단서 추출을 사례마다 나눠 이 수까지 동시에 부름. 1이면 한 번에 (`.env`의 `LLM_MIN_INTERVAL_SEC`가 0보다 크면 나누지 않음, ADR-0035) |
| `--no-compare` | 비교 갈래(방어 없음 C0 · 턴별 방어 C1S) 계산을 끔. 관제 화면의 '다른 방식이었다면'이 비고, LLM 호출이 줄어듦 |
| `--port 8080` · `--host 0.0.0.0` | 주소 |
| `--keep 12` | 의료진마다 메모리에 둘 대화 수 (넘는 대화는 DB에만 남고 읽기 전용) |
| `--cookie-secure` | https로만 로그인 쿠키를 보냄 (역방향 프록시 뒤 https 운영) |
| `--no-rule-extract` | 실제 LLM 대화 · 레드팀의 나이 · 날짜 규칙 추출을 끔. 기본은 켬: 추출기가 날짜를 약 항목 안에만 적어도 날짜를 단서로 셈 (ADR-0021) |
| `--answer-style off` | 실제 LLM 대상 AI의 짧은 답 형식 지시를 끔. 기본은 켬: 의료진 대화와 레드팀에 같이 걸고, 레드팀 실행 기록에 남김 (ADR-0025) |
| `--auto-redteam change` · `--auto-redteam off` | change(기본): 판정 규칙 판 · 답 형식 · 모델 · 규칙 추출이 마지막 점검과 다르면 켤 때 '유형마다 1명' 레드팀을 뒤에서 돌리고 직전 점검과 비교. `--llm real`일 때만 (ADR-0028) |
| `--auto-redteam-daily 03:00` | 매일 그 시각(서버 시계)에도 '유형마다 1명' 레드팀을 돌림 (기본: 안 함) |
| `--extractor-model 모델` · `--rewriter-model 모델` | 추출기(단서 뽑기 · 다시 확인) · 재작성기만 다른 모델로. 질문 하나에 이 둘이 3번쯤 불리므로 빠른 모델을 쓰면 기다림이 크게 준다 (ADR-0026) |
| `--prefetch off` | 차트의 '유사 사례 찾기'에서 진료 목적을 고르면 첫 답을 뒤에서 미리 만들어 두는 것을 끔. 기본은 켬: 열기가 짧아지지만, 고르기만 하고 열지 않은 환자의 호출이 생김 (ADR-0029) |
| `--visit research` | 의료진 대화의 진료 기준을 연구 계획 기준(가장 많이 나온 진단 범주의 첫 진료)으로. 기본 `recent`: 진료 목적마다 가장 최근 진료와 그날 이어지던 동반질환 (ADR-0029) |
| `--ledger off` · `--ledger-window-days 90` | 과거 환자 단위 공개 원장. 기본은 켬: 같은 과거 환자에 대해 다른 대화 · 다른 의료진에게 공개된 값(최근 90일, 0이면 기간 없이)까지 합쳐 판정 (ADR-0032) |
| `--input-gate off` | 대상 AI 입력 게이팅을 끔. 기본은 켬: 사례 기록을 대상 AI에 넣기 전에 값마다 판정해 가릴 값은 '(비공개)', 넓힐 값은 상위 범주, 횟수는 범위로 넣음 (ADR-0032) |
| `--answer-budget 45` | 질문 한 번의 공개 처리 시간 한도(초). 넘기면 확인하지 못한 답 대신 안내 문장(`REFUSAL_TIMEOUT`). 0이면 끔 (ADR-0032) |
| `--sensitivity off` · `--strict-k 10` | 민감도 등급. 기본은 켬: 물질 사용 · 정신 건강 · 생식 · HIV 값은 후보가 10명 이상일 때만 내고, 미성년 시기 물질 사용 장애 과거 환자는 유사 사례 검색에서 뺌 (ADR-0032) |
| `--break-glass off` | 담당 외 환자 예외 열람을 끔: 의료진은 담당 환자와 협진 의뢰로 받은 환자만 엶. 기본은 켬: 등록번호 · 사유 · 설명을 적으면 12시간 열리고 보안 담당자가 검토 (ADR-0034 · ADR-0036) |
| `--db 경로` | DB 파일 (기본 `runs/medicloak/medicloak.db`) |

## 실제 LLM 호출 수

- **환자를 열 때(첫 답, 턴 0)**: 대상 AI 1번, 추출기 1번(형식이 틀리면 다시), 가릴 값이 있으면 재작성기 1번과 확인 추출 1번. 나이 · 날짜를 공개 단위로 맞추기만 하면 재작성기 없이 확인 추출 1번입니다. 사례 검색 질문 문장만 결정적 응답기가 만듭니다. 세 갈래의 첫 판정은 요청이 같아서 앞 갈래가 받은 답을 다시 씁니다(형식 오류 뒤 다시 보내는 요청은 새로 부름).
- **같은 환자 · 같은 진료 목적을 다시 열 때**: 다른 의료진이 연 것이어도 앞서 받은 첫 답을 다시 쓰므로 실제 LLM을 부르지 않습니다(메모리에만 두고 서버를 다시 켜면 비움. 첫 답이 거절이었으면 새로 부름). 여는 동안 화면에 지금 단계와 걸린 시간이 보입니다(`GET /api/emr/launch/progress`).
- **첫 답 미리 준비**: 차트의 '유사 사례 찾기'에서 진료 목적을 고르고 1초쯤 머물면, 위 첫 답(대상 AI · 추출 · 재작성 · 다시 확인)을 뒤에서 미리 부릅니다(`POST /api/emr/prefetch`). 다 받은 뒤 열면 실제 LLM을 부르지 않고, 받는 중에 열면 같은 호출을 기다려 씁니다. 의료진마다 한 번에 하나이고, 도는 중에 다른 환자나 진단을 고르면 마지막으로 고른 것 하나만 이어서 준비합니다. 고르기만 하고 열지 않으면 그 호출은 쓰이지 않을 수 있습니다. 감사 기록에 '첫 답 미리 준비'로 실제 호출 수와 함께 남습니다. `--prefetch off`로 끕니다(ADR-0029).
- **대상 AI 답 형식**: 대상 AI 지시문 끝에 '사례마다 짧은 문장 두세 개, 표 · 머리글 · 굵은 글씨 없이, 묻지 않은 날짜 · 나이 · 지역은 덧붙이지 않음'을 붙입니다. 답이 짧을수록 추출 · 재작성 · 확인이 모두 빨라집니다. 의료진 대화와 실제 LLM 레드팀에 같이 걸어, 방어 효과를 잰 조건과 운영 조건이 같습니다. `--answer-style off`로 둘 다 끕니다(ADR-0024 · ADR-0025).
- **다시 확인을 통과하지 못했을 때**: 두 번째 재작성에는 무엇이 남았는지 알려 주고, 값만 바꾼 답까지 통과하지 못하면 통과하지 못한 사례만 빼고 한 번 더 확인합니다(추출 1번 더). 그래도 안 되면 거절 문장입니다.
- **의료진 질문 한 번**: 위와 같습니다. 비교 갈래 C1S는 의료진 답을 보낸 뒤 뒤에서 계산하므로 의료진은 기다리지 않지만, 값을 바꿀 때 재작성 · 확인 호출이 더 듭니다(`--no-compare`로 끔). C0은 같은 원 응답을 쓰므로 호출이 없습니다.
- **레드팀 점검**: 질의 환자 한 명마다 갈래 3개 × 최대 10턴, 턴마다 공격 질문 만들기 · 확인 · 대상 AI · 추출 · 재작성 · 다시 확인으로 약 6번으로 어림합니다. 유형마다 1명(3명)이면 약 540번입니다. 위험에 닿은 대화는 일찍 끝나 줄고, 형식 오류로 다시 부르면 늘어납니다. 의료진 질문 호출이 기다리면 그쪽을 먼저 보냅니다.

입력 게이팅 · 공개 원장 · 공개 직전 문장 처리 · 민감도 등급은 LLM을 더 부르지 않습니다(서버 안에서 셈). 답 시간 한도를 넘기면 남은 재작성 · 다시 확인 호출을 하지 않습니다.

LLM을 부르지 않는 것: 입력칸의 '보내기 전 확인'과 보안 담당자의 '질문 미리 세기'(사례 기록대로 답한다고 보고 세는 추정), 예시 질문. 대상 AI 이름은 관제 화면 머리줄에, 서버를 켠 뒤의 역할별 호출 수와 토큰은 '보호 정책' 화면(`/api/monitor/policy`)에, 레드팀 실행의 호출 수 · 토큰은 리포트 화면에 나옵니다.

## 계정

```bash
python -m medicloak users                                  # 목록
python -m medicloak users add kim --name 김의사 --role clinician --department 소아청소년과
python -m medicloak users add sec2 --name 박보안 --role security
python -m medicloak users passwd doctor1                   # 비밀번호 바꾸기 (그 계정의 로그인 세션은 모두 끊김)
```

## 담당 배정

외래 환자(115명)마다 담당 의료진과 등록번호(`26-4821`처럼 `26-` + 무작위 네 자리, 처음 정한 뒤 바뀌지 않음)가 있습니다. `init`과 서버를 켤 때, 담당이 없는 환자를 환자 번호 순서대로 담당이 가장 적은 의료진 계정에 하나씩 나눕니다(처음 계정 둘이면 58명 · 57명). 이미 담당이 있는 환자는 옮기지 않으므로, 새로 만든 의료진 계정은 담당이 없습니다. 바꾸는 일은 감사 기록에 남습니다(ADR-0034).

```bash
python -m medicloak assign                                 # 계정마다 담당 환자 수
python -m medicloak assign list --patient 0e7fe2c7         # 한 환자의 담당 (환자 번호 앞 8자리)
python -m medicloak assign add 0e7fe2c7 kim                # 담당 더하기 (한 환자에 여러 명도 됨)
python -m medicloak assign remove 0e7fe2c7 doctor1         # 담당에서 빼기
python -m medicloak assign auto --reset                    # 모두 지우고 지금 의료진 계정으로 다시 나누기
```

## 화면 흐름

1. **의료진** 로그인 → **내 담당 환자**(`/emr`). 왼쪽 목록에는 그 의료진의 담당 환자만 나옵니다. 진료 중 · 완치 · 장기 미내원 탭으로 나뉘고, 줄마다 등록번호 · 성별 · 연령대 · 진료 상태 · 대표 진단 · 마지막 내원일만 보입니다(생년 · 거주 지역은 없음). 연령대는 마지막 내원 때 나이라, 장기 미내원 환자는 '40대(1970년 기준)'처럼 그 해를 같이 적습니다. 환자를 고르면(`/emr/{환자 id}`) 가운데에 **차트 요약**이 나옵니다: 내원 이력(해마다 한 줄: 내원 수 · 1~12월 달력 띠 · 그해 새 진단과 첫 시술. 누르면 그해 내원이 날짜마다 펼쳐지고 처음 나온 기록에 '처음'이 붙음. 오래된 해는 '이전 기록'으로 접힘, ADR-0038), 진단 이력 · 처방 · 시술 · 관리 계획(같은 이름은 묶어 횟수 · 처음 · 마지막 날, 진행 중인 것 먼저). 종료일이 없어도 마지막 처방이 마지막 내원보다 1년 넘게 앞선 처방, 오래된 급성 질환은 '진행 중'이 아니라 '종료일 없음'으로 따로 보입니다(ADR-0037). 차트를 연 일은 접근 기록에 남습니다. 오른쪽 **유사 사례 찾기**에서 진료 목적(처방 · 시술·치료 · 경과·관리)을 골라 엽니다. 진료 목적 카드는 그 목적에 맞는 가장 최근 진료가 기준이고, 그날 이어지던 동반질환이 함께 보입니다. 오늘 볼 문제가 최근 진료와 다르면 카드 아래 '오늘 볼 진단'에서 그 환자의 다른 진단을 골라 그 진료일 기준으로 엽니다(ADR-0029). 이미 연 환자가 있으면 바꾸기 전에 확인을 받고, 지금 연 환자를 고르면 '돌아가기'가 됩니다. 열기가 실패하면 단추 아래에 까닭과 '다시 시도'가 남습니다(앞단이 연결을 끊은 502 · 524면 그렇게 알리고, 서버가 그 사이 답을 마쳤으면 다시 시도할 때 바로 열립니다, ADR-0031). 열기 전에는 유사 사례 조회 화면이 '진료 지원 AI에 연 환자가 없습니다'로 보입니다.
   - **협진 의뢰**: 담당 의료진은 차트 머리의 '협진 의뢰'에서 받을 의료진과 의뢰 내용(5자 이상)을 적어 보냅니다. 받은 의료진의 목록 맨 위 '받은 협진 의뢰'에 등록번호 · 성별 · 연령대 · 보낸 의료진 · 내용이 보이고, '열기'를 누르면 번호를 적지 않고 12시간 열립니다. 의뢰는 7일 동안 유효하고, 받은 사람은 거절, 보낸 사람은 취소(그 의뢰로 연 열람도 끝남)할 수 있습니다. 모두 감사 기록에 남고, 연 열람은 보안 담당자 검토 대기에 '협진 의뢰'로 올라옵니다(ADR-0036).
   - **담당 외 환자 열기**: 당직 · 응급처럼 의뢰 없이 꼭 봐야 하면 목록 아래 단추에서 등록번호 · 사유(협진 · 당직/응급 · 기타) · 설명(5자 이상)을 적어 12시간 엽니다(예전 환자 번호 앞 8자리도 받음). 목록의 '담당 외 환자 · 협진 · 예외 열람'에 남은 시간과 함께 보이고, 감사 기록에 남아 보안 담당자가 검토합니다. `--break-glass off`면 이 단추가 없습니다(협진 의뢰는 그대로, ADR-0034 · ADR-0036).
   - 담당이 아닌 환자의 차트 · 진료 지원 AI · FHIR를 부르면 403이고, 그 거부도 기록에 남습니다.
2. **유사 사례 조회**(`/`)에서 사례에 묻습니다. 사례 하나는 과거 기록의 환자 한 명입니다. 사례 목록 머리에 여러 사례의 공통 값이, 사례마다 다수와 다른 항목이 보이고, '비교'로 사례 × 항목 표를 엽니다. 첫 답이 말하지 않은 사례는 '첫 답에 나오지 않음'으로 보이고, 물어서 답에 나온 값으로 채워집니다. 예시 질문은 조회 목적(처방 · 시술·치료 · 경과·관리)에 맞는 진료 질문이고, '묻는 범위'를 '찾은 사례 전체'로 바꾸면 공통점 · 차이를 한 번에 묻습니다. 질문 문장과 묻는 범위가 어긋나면(사례 하나 범위에서 "이 사례들에서 …") 보내기 전에 범위를 고르라는 안내가 뜹니다. 답을 기다리는 동안 지금 단계(답 쓰기 → 보호 기준 확인 → 필요하면 고쳐 쓰기)가 막대로 보이고, '멈추기'로 그 질문을 멈출 수 있습니다. 멈추면 대화는 묻기 전 그대로이고 질문은 입력칸으로 돌아갑니다. 진료 지원 AI 열기도 같은 방식으로 멈춥니다(ADR-0035). 위 '지금 보는 환자' 띠(진료 지원 AI 대화가 열려 있을 때만 보임)의 'AI에 보내는 요약'을 누르면 대상 AI에 실제로 보내는 환자 요약과 검색 기준이 보입니다. 첫 답과 이후 답 모두 실제 LLM이 쓰고, 환자를 알아볼 수 있는 값은 '범위'나 '비공개'로 보입니다. 실제 LLM이 문장에서 지운 값은 그 사례 줄 끝에 '시기 비공개'처럼 무엇을 가렸는지 이름과 함께 잠금 표시(테두리 · 사선 막대)로 붙고, 같은 사례의 다른 값이 보이면 '다른 처방 약 비공개'로 보입니다(ADR-0028 · ADR-0029). '비공개' · '범위' 표시를 누르면 그 자리에서 어느 사례의 무엇을 왜 바꿨는지(MediCloak이 바꿨고 과거 사례 기록은 그대로라는 것까지) 설명이 뜨고, 답 아래에는 사례마다 가리고 넓힌 항목이 한 줄씩 보입니다(ADR-0037). 사례 문서의 '종료 기록 없음'은 답에 '종료일 없이 계속 처방되었습니다'로 보이고, '약 2년 이상' 같은 기간은 '1년 이상'처럼 겹치지 않게 넓힙니다. 나이는 5세 구간, 날짜는 월보다 자세히 보이지 않습니다. 숫자(후보 수)는 보이지 않습니다. 복용 기간 같은 상대 기간은 날짜와 따로 '약 1~2주'처럼 범위로만 보입니다(묻는 범위와 상관없이 같음). 오른쪽 사례 노트에는 답에 실제로 나온 값만 모입니다. 넓은 화면에서는 노트가 접혀 있고 오른쪽 띠를 눌러 펼칩니다. 세부 정보가 필요하면 답 아래 **세부 정보 요청**을 보내고, 답장 · 확인 요청은 오른쪽 아래 **보호 담당자 창**(머리줄 알림으로도 열림)에서 봅니다(ADR-0031).
   - 요청할 사례를 고를 수 있습니다. 답 아래 요청 창은 그 답에서 값이 바뀐 사례 가운데서, 보호 담당자 창은 모든 사례 가운데서 고릅니다. 알림에서 창을 열면 그 알림의 사례가 기본입니다.
   - 승인 결과는 항목마다 옵니다. 공개한 값에는 어떻게 가렸던 값인지(가렸던 값 · 범위로 보였던 값)를, 이번에 공개하지 않은 값에는 까닭과 대안을 붙입니다. 일부만 공개했으면 요청 상태가 '일부 승인'입니다.
   - 승인한 진단 · 대표 항목은 사례 카드에도 그 값으로 보이고, 카드에 '승인 공개'가 붙습니다.
   - 실제 LLM 대화의 보내기 전 안내는 기록대로 답한다면으로 미리 센 추정이라 "미리 세어 보면 … 표시될 수 있습니다"로 말합니다. 실제로 바꿀 값은 AI 답을 받은 뒤 다시 정합니다. 보호 담당자 규칙 · 조회 목적으로 가리는 것은 확정이라 그대로 말합니다.
3. **보안 담당자** 로그인 → **관제**(`/monitor`). 의료진 이름이 붙은 대화와 요청이 맨 위에 옵니다. 첫 화면의 '기준 5명 아래 사례'는 방어 규칙을 거치고도 내려간 경우(경보)만 세고, 승인 공개로 내려간 사례는 '승인 공개로 기준 아래'로 따로 셉니다. 같은 과거 환자를 최근 30일 안의 다른 대화에서도 물었으면 '같은 과거 환자 다른 대화에서도 조회'로 확인 필요에 올립니다(판정은 바꾸지 않음). 상세에서
   - **세 줄 요약**: 맨 위에 위험했던 것 · 시스템이 한 일 · 내가 할 일이 보입니다. 요청이 온 대화는 요청한 사례가 초점입니다(ADR-0030).
   - **후보 수**: 초점 사례의 지금 후보 수와 환자 기호(`P-3f9a1c`, 번호는 열람 뒤에만)가 보입니다. '자세히'를 누르면 의료진 화면(누적 방어) · 턴별 방어 · 방어 없음의 대화 끝 후보 수를 한 눈금에, 초점 사례에서 후보가 단서마다 어떻게 줄었는지(가린 값은 '그대로였다면')를 봅니다.
   - **원문 열람**: 사유를 고르고 확인하려는 것을 한 줄(5자 이상) 적어야 열립니다. 미리 골라 둔 사유는 없습니다.
   - **검토 보조**: 세부 정보 요청이 오면 검토 보조 에이전트가 뒤에서 초안을 만듭니다(ADR-0027).
     - 가린 값마다 지금 하나만 열었을 때의 후보 수와 조회 목적에 쓰이는 정도를 보고 추천을 정합니다.
     - 추천은 공개 가능 · 사유 확인 뒤 결정 · 지금 범위 유지 · 공개하지 않음 가운데 하나입니다.
     - 공개 가능한 값은 함께 열어도 기준 이상인지 다시 셉니다.
     - 요약과 의료진 답장 초안은 실제 LLM이 씁니다. LLM에는 가린 값의 원문을 보내지 않습니다.
     - 초안은 보내지 않습니다. '승인 창에 담기' · '답장 칸에 넣기'로 담당자가 고쳐 직접 보냅니다.
   - **값 공개 승인**: 세부 정보 요청이 오면 가린 값을 골라 사유를 적고 공개합니다. 값은 그 의료진의 그 대화에만 '공개 승인' 메시지로 가고, 누적 판정에 더해집니다. 관제 화면에서는 공개한 값도 원문 열람 뒤에만 보입니다.
     - 값을 고르면 함께 공개한 뒤의 후보 수를 서버가 셉니다. 기준 아래로 내려가면 '알고 공개합니다' 확인란과 15자 이상 사유를 받고, 고위험 승인으로 감사 기록에 따로 남습니다(2인 확인 대신, ADR-0030).
   - **이 대화에 규칙 걸기**: 사례와 단서 종류를 고르면 다음 질문부터 그 단서는 늘 가립니다. 풀 수 있습니다.
   - 승인과 규칙은 의료진이 지금 열어 둔 대화에만 됩니다. 의료진이 다른 환자를 열었거나 지난 대화이면 막힙니다(409). 걸지 못한 규칙도 감사 기록에 '규칙 걸기 실패'로 남습니다.
   - 같은 메시지를 15초 안에 두 번 보내면(두 번 누름) 한 번만 들어갑니다.
4. **의료진 대화**(`/watch`)에서 대화를 골라 후보가 줄어든 과정, 답마다의 판정 표(단서 · 조치 · 그대로였다면 · 고친 답 다시 확인)와 단서 그래프를 봅니다. 원문은 관제에서 사유를 적어야 열립니다.
5. **리포트**(`/report`)에서 레드팀 점검을 실제 LLM으로 돌립니다. 규모(유형마다 1 · 2 · 5 · 10명, 전체)를 고르면 어림 호출 수를 보여 주고, 진행 · 호출 수 · 토큰 · 남은 시간을 보며 멈출 수 있습니다. LLM 호출이 실패한 질의 환자는 집계에서 빼고 그 수를 보이며, 처음 세 명이 모두 실패하면 오류로 멈춥니다. 결과는 DB에 남고, 결정적 응답기로 잰 기준 평가(2026-10-23)를 참고로 고를 수 있습니다.
6. **EMR 접근**(`/emr-access`)에서 외래 환자마다 기호(`P-3f9a1c`) · 진료 상태 · 담당 · 마지막 접근 · 7일 접근 수 · 예외 열람 수를 봅니다. 진단 · 나이 · 환자 번호는 보이지 않습니다. 환자를 고르면 접근 기록(누가 · 언제 · 무엇을 · 담당인지 예외 열람인지)과 예외 열람이 나오고, 차트는 사유를 고르고 확인하려는 것을 적어야 열립니다(그때 환자 번호와 차트 요약이 보이고 감사 기록에 남음). 예외 열람은 '적절함' 또는 '확인 필요'(까닭 필수, 열람을 바로 끝냄)로 검토합니다. 배정은 보기만 하고, 바꾸기는 `assign` 명령으로 합니다(ADR-0034).
7. **감사 기록**(`/audit`)에 로그인 · 로그아웃 · 실패, EMR 열기와 첫 답 미리 준비(고른 오늘 진단 포함), 담당 외라 막음 · 예외 열람 · 예외 열람 검토 · 보안 담당자 차트 열람 · 담당 배정, 의료진 질문(사례 · 보호한 값 수 · 내보낸 답, 질문 본문은 넣지 않음), 열람(사유 · 적은 내용) · 검토 · 메시지, 공개 승인(항목 · 사유 · 공개 뒤 후보 수 · 고위험 여부, 값은 넣지 않음), 규칙 걸기 · 풀기 · 실패, 레드팀 시작 · 멈춤이 남습니다. 환자를 다룬 기록에는 지금 환자와 사례(과거 환자)의 기호가 함께 남습니다. 기호는 같은 환자면 늘 같아 번호 없이 이어 볼 수 있습니다(ADR-0030).

서버를 다시 켜면 지난 대화는 관제 · 의료진 대화 화면에 '지난 대화'로 남습니다. 열람과 검토 표시는 되지만 메시지는 보낼 수 없습니다. 의료진은 새 대화부터 시작하고, '조회 기록'에 지난 진료가 나옵니다.

## 보안 동작

- 비밀번호: PBKDF2-HMAC-SHA256 200,000회, 계정마다 16바이트 salt. 원문은 저장하지 않습니다.
- 세션: 임의 토큰 32바이트를 HttpOnly · SameSite=Lax 쿠키로 주고, DB에는 SHA-256만 둡니다. 12시간이 지나거나 60분 동안 쓰지 않으면 끝납니다.
- 역할 검사: 미들웨어(라우터와 같은 경로)와 API 경로마다 붙인 검사, 두 곳에서 합니다. 하위 경로 프록시 · `--root-path` 뒤에서도 같습니다. API 문서(`/docs` · `/openapi.json`)는 운영 모드에서 열지 않습니다.
- 로그인 제한: 같은 계정 · 주소에서 10분 안에 5번, 같은 계정에서 20번 틀리면 막습니다(429). 시도는 비밀번호 확인 전에 세므로 한꺼번에 보내도 넘지 못합니다. 없는 아이디는 감사 기록에 입력값을 남기지 않습니다.
- 세션 직접 조작 경로(`/api/sessions/…`, POC 재현 · 테스트용)는 의료진 대화를 열거나 바꾸지 못합니다. 의료진 대화는 관제(사유를 남긴 열람)와 의료진 대화 분석으로만 봅니다.
- API 키: `.env`에서만 읽고 화면 · 로그 · 감사 기록 · 오류 문구에 넣지 않습니다. `check-llm`도 설정 여부만 보여 줍니다.
- 과거 기록 환자: 유사 사례 검색 대상(461명)은 FHIR로 열 수 없습니다(404). 그 기록은 진료 지원 AI 답과 MediCloak 판정을 거쳐서만 보입니다.
- 담당 배정: 외래 환자도 담당 의료진만 엽니다(목록 · 차트 · 오늘 볼 진단 · 진료 지원 AI 열기 · 첫 답 미리 준비 · FHIR). 검사는 여는 때 하므로, 담당이 바뀌어도 이미 열린 대화는 이어집니다. 거부는 같은 요청을 60초에 한 번만 감사 기록에 남깁니다(ADR-0034).
- 예외 열람: 등록번호 · 사유 분류 · 직접 쓴 설명(5자 이상)이 모두 있어야 열리고, 미리 골라 둔 사유는 없습니다. 12시간이 지나거나 보안 담당자가 '확인 필요'로 검토하면 끝납니다. `--break-glass off`로 켜면 열어 둔 것도 쓰지 않습니다(협진 의뢰로 연 열람은 씀).
- 협진 의뢰: 담당 의료진만 보내고, 받은 의료진만 엽니다. 같은 환자를 같은 의료진에게 보낸 열린 의뢰는 하나입니다. 의뢰는 7일, 연 열람은 12시간이고, 취소하면 그 열람도 끝납니다(ADR-0036).
- 등록번호: 무작위 네 자리라 번호를 하나씩 늘려 열어 볼 수 없고, 보안 담당자 화면에는 사유를 적은 차트 열람 때만 보입니다.
- EMR 접근 기록: 차트 열람(1분에 한 번) · FHIR 조회(10분에 한 번) · 진료 지원 AI 열기 · 거부 · 예외 열람 · 보안 담당자 차트 열람을 환자마다 DB(`emr_access`)에 남깁니다. 보안 담당자 EMR 접근 화면은 환자를 기호로만 보이고, 차트는 사유를 적은 열람 때만 보냅니다.
- 원 응답 · 가린 원래 값: DB의 턴 기록과 대화 스냅숏에만 있고, 보안 담당자 API에서도 사유를 남긴 열람 때만 나갑니다.
- 환자 기호: 감사 기록 · 관제 화면에는 환자 번호 대신 `P-` + HMAC-SHA256(키, 번호 앞 8자) 앞 6자를 씁니다. 키는 DB meta `subject_tag_key`에 처음 쓸 때 만듭니다. 화면에서 번호를 가리는 장치이고, DB를 직접 읽는 사람에게는 보호가 되지 않습니다.
- 공개 승인: 사유 5자 이상(함께 공개하면 후보가 기준 아래로 내려가는 공개는 확인 표시와 15자 이상), 공개 목록(`/hidden`)과 승인 응답에는 값이 없고, 값은 승인 메시지로 그 의료진의 그 대화에만 갑니다. 관제 상세 · 메시지 목록은 열람 전에 공개한 값을 지웁니다. 감사 기록에는 항목과 사유, 요청한 사례에서 이번에 공개하지 않은 단서만 남습니다. '공개 승인' 메시지는 승인 경로로만 보낼 수 있습니다.
- 고친 답 다시 확인: 가리거나 넓히기로 한 원래 값이 글자 그대로 남았거나, 사례 표기가 사라져 사례를 찾지 못하면 통과시키지 않고 값만 바꾼 답 · 거절로 넘어갑니다. 실제 LLM 레드팀도 같은 확인을 씁니다(ADR-0022).
- 최소 공개 단위: 실제 LLM 답의 나이는 5세 구간(93세 → 90~94세), 날짜는 월(2018-03-24 → 2018-03)보다 자세히 내지 않습니다. 답의 글자가 후보를 센 노드보다 자세하면(노드 90~99세로 센 '93-98세') 노드 이름으로 바꿉니다. 이것만 바꾸면 재작성기 없이 글자를 바꾸고 다시 확인합니다(공개 방식 `ROUNDED`). 보안 담당자의 공개 승인은 정확한 값을 엽니다(ADR-0024).
- 사례 노트: 내보낸 답을 다시 추출해 State에 넣은 단서와 맞춰, 답에 실제로 나온 글자만 적습니다. 재작성기가 뺀 값은 노트에도 없습니다.
- 조회 목적 규칙: 거주 지역은 어느 조회 목적에도 진료 판단에 쓰지 않아, 실제 LLM 갈래(의료진 대화 · 레드팀)에서 후보 수와 관계없이 가립니다. 세부 정보 요청 · 공개 승인 대상도 아닙니다(ADR-0026).
- 과거 환자 단위 공개 원장: 의료진 대화에서 공개된 값과 승인 공개한 값을 과거 환자마다 DB(`disclosure_ledger`)에 적고, 같은 과거 환자가 나온 다른 대화의 판정(출력 단계 · 입력 게이팅 · 공개 승인 · 보내기 전 확인)에 최근 90일 값을 합칩니다. 이 대화에서 값이 나간 사례가 다른 대화와 합치면 기준 아래이면 관제 목록에 '다른 대화와 합치면 기준 아래'로 올라옵니다. 의료진 화면에는 숫자 없이 '다른 진료 대화에서 이미 공개된 정보까지 합쳐 판단했습니다'만 보입니다(ADR-0032).
- 대상 AI 입력 게이팅: 사례 기록을 대상 AI에 넣기 전에 사실 줄마다 그 사례의 지금 State(원장 포함)로 출력 단계와 같은 판정을 합니다. 가릴 값은 '(비공개)', 넓힐 값은 상위 범주 이름, 횟수는 범위, 가리거나 넓힌 날짜 사이 기간은 '(시작부터 약 1~2주)'로 넣고, 지시문에 짐작해 채우지 말라는 한 줄을 붙입니다. 첫 답(열 때 · 미리 준비)과 다음 질문 모두 그때 State로 다시 게이팅합니다(ADR-0032).
- 공개 직전 문장 처리: 사례 문장의 기간 · 간격 · 횟수는 범위로, '…만 처방' · '다른 약은 없음' · '처방 약이 없습니다' 같은 부재 · 배타 진술과 기록에 없는 원인 · 목적 짐작은 빼거나 고칩니다. 남는 말이 없으면 '기록으로 확인할 수 없는 부분은 답에서 뺐습니다' 한 줄을 보냅니다. 레드팀 실제 LLM 갈래에도 같이 걸립니다(판정 규칙 v7, ADR-0032).
- 날짜 값 바로잡기: 추출기가 날짜 자리에 설명('…진단 시작')을 쓰고 날짜는 근거 문장에만 두거나, 답에 '2014년 4월 1일' · '2014.04.01' 꼴로 나온 날짜를 정규화기가 읽는 꼴로 바꿔 판정에 넣습니다. 전에는 정규화가 실패해 그 날짜가 위험으로 세어지지 않고 그대로 나갈 수 있었습니다(RAG 재측정 원본 대조에서 찾음, 판정 규칙 v8, ADR-0033).
- 민감도 등급: 물질 사용 · 정신 건강 · 생식 · 피임 · 임신 · HIV · 성매개 감염 값(약 이름으로 거꾸로 알 수 있는 것 포함)은 후보가 `--strict-k`명 이상일 때만 내고, 아니면 민감하지 않은 상위 범주로 넓히거나 가립니다. 입력 게이팅과 출력 단계가 같은 규칙입니다. 미성년 시기 물질 사용 장애 과거 환자는 유사 사례 검색에서 뺍니다(ADR-0032).
- 답 시간 한도: 질문을 받은 때부터 `--answer-budget`초를 넘기면 확인하지 못한 답을 내보내지 않고 안내 문장을 보냅니다. State와 원장은 바뀌지 않습니다(ADR-0032).
- 미리 확인 한도: 의료진 '보내기 전 확인'은 대화마다 10분에 20번(넘으면 판정 없이 안내만, 감사 기록), 보안 담당자 '질문 미리 세기'는 계정마다 10분에 30번(넘으면 429)이고 부를 때마다 감사 기록에 사례와 질문 글자 수만 남깁니다(ADR-0032).
- 거절 전에 사례 단위로 빼기: 재작성 · 값 치환이 모두 통과하지 못하면, 통과하지 못한 사례를 가리키는 머리줄 묶음과 문장만 빼고 다시 확인합니다. 통과하면 그 답을 내고(공개 방식 `CASE_DROPPED`), 뺀 사례는 의료진 화면에 '(비공개)'로 보입니다. 낸 답은 늘 다시 확인을 거칩니다. 재작성기 지시에는 같은 값이 요약 문장 · 줄인 이름으로 다시 나와도 고치라는 규칙을 더하고, 두 번째 재작성에는 남은 표현을 알려 줍니다. 실제 LLM 대화와 레드팀에만 적용합니다(ADR-0023).

## 운영 가이드

병원에 실제로 놓을 때 코드 밖에서 정해야 하는 것들입니다.

- **대상 AI로 나가는 데이터**: 대상 AI 지시문에는 검색된 과거 환자 기록(진단 · 약 · 날짜 등)이 들어갑니다. MediCloak이 지키는 것은 의료진 화면으로 나오는 답입니다. 외부 LLM API를 쓰면 기록이 제공사로 나가므로 다음 중 하나가 필요합니다.
  - 병원 내부 모델
  - 계약으로 보호되는 전용 환경
  - 보내기 전 가명처리
- **보호 담당자 운영**: 세부 정보 요청은 사람이 승인합니다.
  - 진료 중 응답 시간 목표와 당직, 메신저 알림 연동이 필요합니다.
  - 승인한 값은 그 대화에서 계속 유효하고, 지금은 철회할 수 없습니다.
  - 검토 보조가 추천을 정할 때 쓰는 조회 목적 표(`assist.PURPOSE_NEED`)는 진료과와 함께 정합니다.
  - 검토 보조는 재작성기 모델로 요청마다 한 번 부릅니다.
- **모델 · 지시문 변경**: 판정 규칙 판 · 답 형식 · 모델 · 규칙 추출이 바뀐 채로 서버를 켜면 '유형마다 1명' 레드팀이 자동으로 돌고, 끝나면 직전 점검과 누적 방어 지표를 비교합니다(ADR-0028).
  - 나빠지면 관제 화면 위와 리포트에 '경고' · '주의'가 뜹니다.
  - 질의 환자 3명 규모라, 경고가 나오면 규모를 키워 다시 확인합니다.
  - 매일 돌리려면 `--auto-redteam-daily`, 끄려면 `--auto-redteam off`입니다.
- **속도와 비용**: 질문 하나에 실제 LLM을 3~4번(최악 8번) 부릅니다. Haiku 4.5 실측으로 질문 하나에 평균 약 19초이고, 대부분 추출과 다시 확인입니다. `--extractor-model` · `--rewriter-model`로 빠른 모델을 쓰고, `--no-compare`로 비교 갈래 계산을 끌 수 있습니다. 의료진 질문 호출은 뒤에서 도는 비교 갈래 · 미리 준비 · 레드팀 호출을 기다리지 않습니다. 같은 환자 · 목적의 첫 답은 메모리에서 다시 쓰고, 차트에서 진료 목적을 고르면 미리 만들어 둡니다.
- **장애**: LLM 호출이 실패하면 질문은 '보내지 못했습니다 · 다시 보내기'로 남고, 대화 상태는 바뀌지 않습니다. 사례 목록과 노트는 그대로 보입니다.
- **감사 기록**: 보관 기간과 점검 주기를 정합니다. 관제의 '같은 환자 반복 질문' · '같은 과거 환자 다른 대화에서도 조회' 표시와 감사 기록의 '고위험' 승인을 정기 점검 항목으로 둡니다.
- **기준 집단**: 후보 수는 과거 기록 환자 전체(지금 461명)를 기준으로 셉니다. 환자가 늘면 스냅숏을 다시 내보내고 서버를 다시 켭니다.

## 범위와 한계

- 실제 모델 호출은 이 저장소 작업 환경에서 확인하지 못했습니다(키 없음). 가짜 HTTP 세션으로 같은 코드 경로(첫 답 · 질문 · 레드팀)를 테스트했고, 처음 켤 때 `check-llm`으로 확인합니다.
- 레드팀 전체(296명)는 호출이 수만 번입니다. 유형마다 1명부터 돌려 보고 늘리세요. 서버를 끄면 돌던 실행은 '끊김'으로 남고 집계하지 못합니다.
- 승인 공개는 그 대화에서 계속 유효하고, 지금은 취소할 수 없습니다.
- 합성 데이터(Synthea 576명, 모두 Massachusetts)입니다. 실제 환자 정보는 없습니다.
- 서버 한 대 · SQLite입니다. 병원 SSO, 실제 EMR(SMART on FHIR) 연동, https 종단은 아직 없습니다.
- 담당 배정은 규칙과 명령으로만 정합니다. 진료 일정(예약 · 접수)과 이어지지 않고, 예외 열람 검토에 기한 · 알림이 없습니다(ADR-0034).
- 서버를 다시 켜면 진행 중이던 대화는 이어 갈 수 없고 읽기 전용으로 남습니다.
- 개인정보보호법 · 의료법상 검토(가명정보 처리, 접속기록 보관 기간 등)는 코드 밖에서 해야 합니다.
- 진료 상태는 가상 EMR의 마지막 기록일 기준입니다(오늘 기준이 아님). 끝나지 않은 진단이 있어도 마지막 기록이 3년보다 오래되면 '장기 미내원'입니다.
- 첫 답 나눠 쓰기는 서버 메모리에만 있습니다(키는 요청의 SHA-256). 서버를 다시 켜면 처음 여는 환자는 다시 실제 LLM을 부릅니다.
- 실제 LLM 레드팀 결과는 답 형식 설정에 따라 달라집니다. 리포트 화면의 실행 이름에 '짧은 답 지시' · '답 형식 지시 없음'이 보이니 같은 설정끼리 비교하세요.
- 상대 기간(복용 기간 등)은 후보 수 계산에 없습니다. 정해 둔 범위로만 보이고, 노트에는 '기간'으로 남지만 판정에는 세지 않습니다(ADR-0029).
- 추출기가 빠뜨린 진단 · 시술 · 약 · 관리 계획 · 거주 지역은 사례 문서에 그대로 있는 표현일 때만 보탭니다. 문서와 다르게 바꿔 쓴 표현은 추출기에 맡깁니다.
- 의료진 대화의 진료 기준(가장 최근 진료)은 레드팀이 쓰는 연구 기준과 다릅니다. 방어 효과는 연구 기준 대화로 잰 값입니다.
- 실제 LLM 대화의 보내기 전 확인은 대상 AI를 부르지 않고 '기록대로 답한다면'으로 미리 셉니다. 실제 답이 기록과 다르게 나오면 가리는 값도 다를 수 있습니다(ADR-0031).
- 대상 AI와 재작성기에 '기록에 없는 원인 · 목적을 짐작하지 않는다'는 지시를 넣었습니다(판정 규칙 v6). 지시일 뿐이라, 짐작 문장이 실제로 줄었는지는 실제 LLM으로 확인해야 합니다.
- 입력 게이팅을 켜면 세 갈래가 같이 쓰는 원 응답이 게이팅된 지시문으로 받은 답입니다. 그래서 관제 화면의 '방어 없음(C0)'은 '출력 단계 방어 없음'이고, 게이팅 전 기록보다 후보 수가 높게 나옵니다(ADR-0032).
- 레드팀은 공개 원장 · 입력 게이팅 · 민감도 기준을 쓰지 않고 공개 직전 문장 처리만 받습니다. 리포트의 방어 효과는 출력 단계 방어의 값입니다.
- 입력 게이팅은 값을 하나씩 판정합니다. 여러 값을 함께 말해 후보가 줄어드는 것은 출력 단계가 막습니다. 게이팅으로 대상 AI가 보는 정확한 날짜가 크게 줄어, 답이 '(비공개)'를 자주 말할 수 있습니다. 답 품질은 실제 LLM으로 확인해야 합니다.
- 부재 · 배타 진술과 짐작 문장은 한국어 표현 규칙으로 찾습니다. 규칙에 없는 표현은 그대로 나갈 수 있고, '…만'을 조사로 바꿀 때 영문 이름의 받침은 어림합니다.
- 공개 원장의 기간 창 밖 기록은 판정에 쓰지 않지만 DB에는 남습니다. 보존 기간과 삭제는 운영 정책으로 정해야 합니다.
- 후보 수(k)는 '누구인지'가 드러나는 것을 막습니다. 후보 전원이 같은 값을 가지면 그 값은 알려질 수 있습니다(동질성). 이 부분은 연구 과제로 남아 있습니다(ADR-0025).
