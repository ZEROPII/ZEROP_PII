# 출력 토큰 분석 — 추출기 출력 한도 결정 근거

- 자료: `runs/medical/run_20261107_151400/llm_usage.jsonl` (914행, 읽기 전용으로 사용, 원본 변경 없음)
- 실행 조건: C0·C1, exploration, budget 12, trials_per_cell 5, 30 trial, 모델 claude-haiku-4-5-20251001, 커밋 0b44873
- 백분위 산출: 선형 보간 (Hyndman–Fan type 7, numpy 기본값). 최근순위법(nearest-rank)으로도 계산했고 결과가 같다(아래 표 괄호).
- 잘림(truncated) = 응답 `stop_reason == "max_tokens"` (`core/llm_client.py` `LLMResponse.truncated`).

- 잘리지 않은 호출만 보면: extractor 89건 최대 2,043, target 73건 최대 1,189.
- 잘린 162건(extractor)·59건(target)은 모두 정확히 상한값(2,048 / 1,200)으로 기록되어 있다. 이 값은 **실제로 필요한 출력 길이가 아니라 상한에서 검열(censoring)된 관측값**이다. 실제 필요 길이는 상한보다 크다는 것만 알 수 있다.

## 2. 요청서 공식 적용

`new_max_tokens = ceil(P99 × 1.25)`

| 역할 | P99 | 계산 | 결과 |
| --- | --- | --- | --- |
| extractor | 2,048 | ceil(2,048 × 1.25) | **2,560** |
| target | 1,200 | ceil(1,200 × 1.25) | 1,500 (적용하지 않음) |

추출기는 P50부터 이미 상한에 걸려 있으므로 P99는 분포의 꼬리가 아니라 상한 자체다. 따라서 2,560은 "필요 길이의 P99 × 1.25"가 아니라 **하한 기반 추정**이다. 2,560으로도 잘림이 남을 수 있다.

## 3. 잘림이 추출 실패의 주 원인인지 (진단)

기존 로그에는 호출과 trial을 잇는 키가 없다. 대신 실행이 단일 스레드 순차 호출이라는 점을 이용해, 코드 경로(make_prefix → 갈래별 턴 → 변형·검사 → 대상 → 추출 1~3회 → 재작성·확인 추출)대로 기대 역할 순서를 만들고 실제 `llm_usage.jsonl` 역할 순서와 한 줄씩 대조했다 (`부록_호출재구성/reconstruct.py`).

- **914/914행이 기대 순서와 정확히 일치**했고, 턴마다 `release_extraction_tries` 합계도 일치했다. 어긋나면 중단하도록 작성했다.
- 이는 기록된 연결 키가 아니라 **순서 재구성**이다. 1행이라도 어긋났다면 연결을 포기했을 것이다.

재구성 결과 (원 응답 추출 = raw, 공개 확인 추출 = verify):

| 항목 | 값 |
| --- | --- |
| raw 추출 시도 | 236 (성공 80 · 실패 156) |
| raw 실패 시도 중 잘림 | **156 / 156** |
| raw 잘린 시도 중 파싱 성공 | 0 |
| C1 `REFUSAL_EXTRACTION_FAILED` 34건 | 34건 모두 3회 시도 × 3회 잘림 (턴 0: 24건, 턴 ≥1: 10건) |
| C0 원 응답 추출 실패 턴 | 42 (턴 0: 24, 턴 ≥1: 18), 모두 3회 × 3회 잘림 |
| verify 추출 | 15 시도 중 잘림 6 (성공 여부는 시도별로 기록이 없어 분류하지 않음) |

**판단:** 추출 실패는 관측 범위에서 전부 출력 잘림에서 생겼다. JSON 형식 오류(잘림 없이 파싱 실패)는 0건이다. 요청서 §2-2-2의 조건("진단 결과가 잘림이면")을 충족하므로 extractor 한도만 **2,048 → 2,560**으로 바꿨다 (`medical/llm.py` `MAX_TOKENS`).

## 4. 대상 모델(target) 한도를 바꾸지 않은 이유

- target 잘림 44.7%는 추출 실패와 별개 문제다 (34건의 실패 턴 중 target이 잘린 턴은 9건뿐).
- target 한도는 대상 AI가 몇 개의 단서를 말하는지를 직접 바꾸는 **실험 조건**이다. 바꾸면 C0 기준선과 위반율 의미가 달라진다. 요청서도 target은 "p99 기준을 확인"만 요구한다.
- 따라서 1,200을 유지하고 검토 사항으로 남긴다 (검증_메모.md §7).

## 5. 참고: 같은 출력의 재시도

온도 0에서 추출 재시도 3회가 모두 같은 길이(2,048)로 잘렸다. 같은 입력·같은 온도의 재시도는 잘림을 풀지 못하고 토큰만 3배 쓴다. 재시도 규칙(max_extract_retries=2)은 판정 기준에 해당하므로 바꾸지 않았다.
