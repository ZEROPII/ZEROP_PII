# 35쪽 결과 · 보호–활용 기준 민감도 (오라클 모의 실행)

작성일: 2026-11-07 · 상태: 모의 실행 결과 (LLM 호출 없음). 실제 LLM 실행 결과가 아닙니다.

## 1. 질문

교수님 지적: 개인정보 단서 그대로 공개율 63.8%가 높다. 방어 기준을 강하게 하면 공개율은 내려가지만 의료 답변 품질도 떨어진다. 어느 기준이 합리적인가?

## 2. 방법

- 방어 기준 세 가지를 비교했습니다. 일반화 기준 · 억제 기준으로 표기합니다.
  - 5/3 (저장소 기본값), 10/5, 20/10
- 같은 질의, 같은 공개 순서에서 세 기준을 돌렸습니다. 실행 조건: 모의 대상 AI(`--profile staged`), 균등 탐색(`--fuzzer uniform`), efficiency 모드, 턴 0~7, 위반 기준 k<5.
- 모의 실행 코드: `medical.simulate` (커밋 `4384f5f`). 기준값만 바꾸고 저장소 파일은 건드리지 않았습니다.
- 5/3 실행은 기존 발표 수치(95.6%, 83.1%, 0%, 63.8%, 87.2%, 9.3%)와 똑같이 재현됐습니다.

## 4. 해석

- 교수님 질문에 대한 근거: 그대로 나간 개인정보 단서 63.8%는 식별 기여가 0이었습니다. 실제 위험은 재식별 확률 상한(1/k)과 최소 k로 봐야 합니다.
- 기준 선택의 교환: 10/5 또는 20/10은 재식별 확률 상한을 낮추지만 정보 유지율을 떨어뜨립니다.
- 방어 우선순위: 기여도가 큰 진료 기간·약·진단을 우선 확인하는 것이 효율적입니다. 특히 진단은 현재 방어가 거의 지우지 않으므로 검토가 필요합니다.

## 5. 한계와 미해결 사항

1. 오라클 모의 실행입니다. 실제 LLM 답변 품질은 확인하지 않았습니다. 가이드의 실제 LLM 실행(기준 10/5, 20/10)은 아직 하지 않았습니다.
2. 정보 유지율 정의가 두 가지입니다. 턴 단위(56.7%)와 판정 단위(70.8%)가 다릅니다. 발표 전에 하나로 통일해야 합니다.
3. C1 재계산 불일치가 남아 있습니다. C0 최종 상태에서는 1,480건 모두 일치했지만, C1S와 C1의 턴별 재계산 불일치 건수는 아직 따로 확인하지 않았습니다.
4. Shapley는 속성 8개를 플레이어로 본 결과입니다. 같은 속성 안의 단서 값 차이는 반영하지 않았습니다.
5. 식별 여부 기준의 Shapley 값은 대부분 0.1 이하입니다. 단독 식별이 드물다는 뜻이지만, 표본 크기에 따라 달라질 수 있습니다.
6. 기준 민감도는 3개 지점만 봤습니다. 곡선을 그리려면 기준을 더 늘려야 합니다.

## 6. 재현

```bash
# 기준 10/5, 20/10은 래퍼에서 generalize_threshold / suppress_threshold를 바꿔 실행

python scripts/shapley.py
```
