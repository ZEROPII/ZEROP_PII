# 단서 추출 개선 : 보류 검증 요청 (개발자용)

개선 규칙은 r3_rule 실행 기록(질의 환자 3명)을 보고 만들었습니다.
그 기록으로 낸 F1 0.925는 개발 기록 기준이라, **규칙을 만들 때 보지 않은 새 기록**으로 다시 재야 합니다.

## 1. 규칙은 고정 상태입니다

아래 세 파일은 지금 상태 그대로 씁니다. 수정하지 말아 주세요. 해시는 `고정본_해시.txt`에 있습니다.

- `extract_eval_v4.py` : 단계 0~4 채점
- `extractor_recall.py` : 기존 채점(정답 정의)
- `normalize_bridge_v0.11.2.patch` : 참고용. 채점 스크립트 안에 같은 규칙이 들어 있어서 적용하지 않아도 됩니다.

- **추출기도 고정해 주세요.** 규칙 추출기는 GitHub에 없어서 우리가 고정할 수 없습니다. r3를 돌린 것과 같은 추출기 · 프롬프트 · 모델 버전을 써 주시고, 그 커밋 해시(또는 버전)를 결과와 함께 적어 주세요. 추출기가 바뀌면 개선 효과가 규칙 덕인지 추출기 덕인지 구분할 수 없습니다.

## 2. 새 기록 만들기

- **설정:** r3_rule과 같은 설정으로 실제 LLM 실행을 합니다. 단계 공개형 · 규칙 추출기(`rule_extract`) · C0 · `--mode exploration` · `--budget 4` · `--docs template`.
- **질의 환자:** r3보다 많은 질의 환자로 돌려 주세요. 예: `--limit 12`.
  - r3에서 쓴 질의 환자 3명은 채점할 때 자동으로 빠집니다(`--exclude`).
  - 다만 검색되는 사례 문서는 r3와 겹칠 수 있습니다. 결과를 보낼 때 겹친 사례 수도 적어 주시면 좋습니다.
  - 남는 질의 환자가 최소 6명 이상이면 좋습니다.
- **명령 예시:** 규칙 추출기 옵션은 로컬 설정에 맞춰 주세요.

```bash
python -m medical run --arms C0 --mode exploration --budget 4 --docs template --limit 12 --out runs/medical/holdout_1
```

## 3. 채점

```bash
python extract_eval_v4.py runs/medical/holdout_1 extractor_recall.py --exclude r3_trial요약.json
```

- 첫 줄 "평가 trial N개 (제외한 질의 환자 3명)"을 확인해 주세요.
- 출력 전체를 그대로 보내 주세요.

## 4. 지켜 주실 것

- 새 기록의 오답을 보고 규칙을 고치지 말아 주세요. 고치면 이 기록도 개발용이 되고, 검증은 또 다른 새 기록으로 다시 해야 합니다.
- 결과가 나빠도 그대로 보고해 주세요. 발표 숫자는 이 결과로 정합니다.

## 참고 : 이미 확인한 것

- **회귀 확인 (범위 한정):** 오라클 추출기 기록(`runs/medical/sim_check`, 대화 6개)에 규칙을 적용해도 0~4단계 결과가 같았습니다(정밀도 100%, F1 0.997).
  - 이는 "기존에 잘 되던 정상 표기의 결과를 바꾸지 않는다"는 뜻입니다.
  - 오라클 기록에는 물결 기간이나 나열 같은 표기가 없어 규칙이 거의 작동하지 않았습니다. 그래서 **실제 LLM 답에서 규칙이 잘못 작동하는지는 이 확인으로 알 수 없고**, 보류 검증에서 확인해야 합니다.
