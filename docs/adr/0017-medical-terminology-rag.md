# ADR-0017. 의료 용어는 RAG 용어 사전으로 설명하고 화면 세 곳에 붙인다

## 배경

11주 차 스크럼에서, 보안 담당자가 판정 근거에 나오는 진단 · 약 · 시술 이름을 몰라 "왜 이 단어가 상위 범주로 바뀌었는지"를 읽기 어렵다는 문제가 나왔다. 화면을 쓰는 사람은 의료 전문가가 아니다.

## 결정

- 용어 DB: 온톨로지 노드 기준 SQLite FTS5. 진단 709 · 약 752 · 시술 133, 총 1,594개(576명 기준).
- 쉬운 설명은 DB를 만들 때 LLM으로 한 번 만들어 저장한다. 화면에서는 LLM을 부르지 않는다.
- API: 검색, 단건(일반화 체인 포함), 목록 3개(이유진).
- 화면(11월 3일 연동): 보안 담당자 `용어` 메뉴, 위쪽 `용어` 버튼으로 여는 옆 패널, 답변 속 용어 자동 표시(밑줄 · 칩).
- 의료진 화면(`view=clinician`)에서는 기준 집단 환자 수(`k_patients` · `total_patients`)를 빼고 보낸다.
- DB 파일이 없으면 노드 표로 메타데이터만 담은 DB를 임시 폴더에 만들어 쓴다(설명은 비어 있음). DB 파일은 커밋하지 않는다.

## 근거

- 미리 만든 설명을 쓰면 응답 지연과 호출 비용이 없고, 같은 용어에 항상 같은 설명이 나온다.
- 노드 ID로 연결해야 Defender의 일반화 체인(예: 세부 진단 → 상위 범주)을 같은 카드에서 보여 줄 수 있다.
- 기준 집단 환자 수는 보안 담당자에게는 판정 근거지만 의료진에게는 필요 없는 위험 정보다.

## 검토한 대안

- 볼 때마다 LLM에 용어 설명 요청: 지연 · 비용이 생기고 설명이 매번 달라진다.
- 외부 의학 사전 링크: 온톨로지 노드와 연결되지 않아 일반화 체인을 보여 줄 수 없다.

## 결과와 영향

- 데모 서버(LLM 0)에서도 용어 화면이 동작한다.
- 용어 별칭 중 코드 · 영문 변형 같은 잡음은 카드에서 걸러 낸다.
