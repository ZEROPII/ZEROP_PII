# ADR-0007. 공개 전 판정을 허용 · 일반화 · 억제 세 단계로 나눈다

## 배경

[ADR-0002](0002-suppress-threshold-three.md)의 기준 하나(k ≤ 3 억제)로는 k가 4나 5처럼 여전히 좁은 응답을 그대로 내보내야 했다. 상위 값으로 넓혀서 내보낼지, 지울지를 나누는 기준이 없었다. 8주 차 스크럼에서 이 문제를 다뤘다.

## 결정

기준을 두 개로 나눈다: `generalize_threshold = 5`, `suppress_threshold = 3`.

| 그 단서를 그대로 냈을 때 k | 처리 |
| --- | --- |
| k > 5 | 원문 그대로 허용 |
| 3 < k ≤ 5 | 부모 방향으로 올라가며 처음 k > 5가 되는 값으로 일반화. 없으면 k > 3인 값, 그것도 없으면 억제 |
| k ≤ 3 | 일반화를 시도하지 않고 바로 억제 |

- 루트(ANY)까지 올라간 일반화는 "말하지 않음"과 같으므로 억제로 기록한다.
- 사례(과거 환자)가 여러 명이면 사례마다 따로 판정한다.

## 근거

- 일반화를 먼저 해서 정보를 덜 잃게 한다. 단, 이미 3명 이하로 좁혀진 경우는 넓혀도 남는 정보가 적어 바로 억제한다.
- ADR-0002 실험에서 억제 기준 3이 정보 손실이 가장 적었다.

## 검토한 대안

- 의사결정 보고서 방식(일반화를 먼저 탐색하고 억제는 최후 수단, 기준 = min(5, 직전 k)): `--backend ontology`로 별도 구현해 비교할 수 있게 뒀다.
- 위험하면 응답 전체 거절: 정상 질문까지 막아 유용성이 크게 떨어진다.

## 결과와 영향

- 의료판도 이 정책을 그대로 쓴다([ADR-0012](0012-event-level-kcalc.md)).
- 10월 23일 모의 POC에서 C1이 고친 단서는 31%였고, 그중 90%가 억제였다. 억제의 82%는 원래 k가 3 이하라 일반화를 시도하지 않은 경우였다.

## 남은 일

기준 5 · 3과 의사결정 보고서의 k_req 5를 어떻게 맞출지 팀 결정이 필요하다([ADR-0004](0004-candidate-count-k-as-risk.md) 남은 일과 같음).
