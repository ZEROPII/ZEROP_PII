# ADR-0043. 사용자 입장 최종 점검

## 배경

2026-11-08 팀 검토에서 의료진이 실제로 쓰는 차례대로 화면을 다시 밟아 보고, 방어 · 답 · 지표가 맞게 도는지와 말투가 어색한 곳을 찾기로 했다. 실제 운영 DB 사본(시험용 비밀번호로 바꾼 것, 저장소에 넣지 않음)을 시연 모드(LLM 없음)로 띄워 의료진 · 보안 담당자 화면을 모두 열었고, 공개 원장의 기록으로 후보 수를 다시 셌다. 다음이 나왔다.

- **방어 결함.** 공개 원장(ADR-0032)을 켠 대화에서, 이 대화만으로 후보 1명이 되는 새 값(처방 시작 시기)을 후보 4명으로 세어 그대로 냈다. 사건 묶음 보정(`medical/grouping.py`)은 공개 값끼리 맞는 환자가 없으면(후보 0명) 먼저 나온 값을 믿고 뒤의 값을 빼거나 묶음을 나눈다. 판정은 원장 값(다른 대화의 추출, 달이 틀리거나 묶음이 다른 잡음이 섞임)을 앞에, 이 대화의 값을 뒤에 두었다. 그래서 원장과 맞지 않는 이 대화의 새 값이 빠졌고, 실제 환자는 후보에도 없었다. 값을 더했는데 후보 수가 커질 수 있다는 뜻이다.
- **답 말투.** 기록의 '종료 기록 없음'을 대상 AI가 '종료일에 도달하지 않았습니다', '종료되지 않았습니다'로 옮겼다. ADR-0037의 '종료일 없이 계속 처방되었습니다'도 무엇이 이어지는지 바로 읽히지 않는다. 팀은 '현재까지 계속 처방되고 있습니다'처럼 지금 이어지는 일로 쓰자고 했다.
- **값을 빼고 남은 문장.** 재작성기가 지역 · 날짜를 빼면서 '사례1 환자는 거주했습니다', ': 시작하여 3회 처방되었습니다'처럼 뜻이 끊긴 문장이 남았다. 약 이름 옆에 기록에 없는 용도를 괄호로 덧붙인 답도 있었다.
- **횟수 범위.** '5회 이상'을 범위로 바꾸면 '4~9회 이상'처럼 말이 겹쳤다.
- **답 시간.** 재작성이 필요한 답은 추출기 호출이 두 번 이상이다. 실행 기록의 추출기 지연은 중앙값 16.6초, 가장 긴 것 64.8초였다(Haiku 4.5, 대상 호출 중앙값 6.7초). 45초 한도에서는 고쳐 쓴 답이 자주 시간 초과로 거절되었고, 그때 본문이 식별 위험 거절 문장이라 의료진이 질문이 위험했다고 오해했다.
- **화면.** 진료 지원 AI 화면 오른쪽 아래의 '보호 담당자에게 묻기' 단추가 입력칸 아래 상태 줄(보내기 전 확인 결과)과 보내기 단추 아래쪽, 펼친 사례 노트를 가렸다. 답의 출처 표시 '기록 16'은 무엇인지 알기 어려웠고, 날짜 값이 '1998'처럼 단위 없이 나왔다. 시연 모드는 질문 하나에 정해 둔 항목만 답하는데, '몇 살 때 진단받았고 어디에 살았나요?'처럼 두 가지를 물으면 하나를 말없이 빠뜨렸다.

같은 점검에서 다음 두 가지는 바뀐 것이 아니라 보이는 조건이 있다는 것을 확인했다. '찾은 사례 전체에 묻기'(공통 처방 · 사례 5건 전체 질문)는 실제 LLM 대화에서만 보인다(시연 모드는 사례 하나씩 답한다). 보내기 전 확인은 그대로 있고 입력하는 동안 입력칸 아래 오른쪽에 나온다(위 단추에 가려 보이지 않았다).

## 결정

### 1. 묶음 보정이 일어나면 이 대화 값만 센 수와 작은 쪽을 쓴다 (`review.OwnStateKC`, `Session.k_global`)

- Defender가 쓰는 후보 수 계산을 `OwnStateKC`로 감싼다 (`RuleDefender`가 한 번만 감싼다). 판정에 넘기는 값 가운데 원장에서 온 것에 `prior` 표시를 붙인다 (`RuledArmRun._basis`).
- 원장 값을 앞에 둔 차례(판정 전과 같음)로 센다. 묶음 보정이 일어났으면(`CONFLICT_DROPPED` · `REGROUPED`) 이 대화의 값(State와 새 값)만으로도 세어 작은 쪽을 쓴다. 보정이 없으면 차례와 상관없이 수가 같으므로 한 번만 센다.
- 이 대화 값만 셀 때도 보정이 일어났으면 새것부터 둔 차례로도 세어 작은 쪽을 쓴다. 한 대화 안에서 앞의 추출 잡음이 새 값을 밀어내는 경우를 줄인다.
- 판정은 더 보수적으로만 바뀐다. 보안 담당자 화면의 원장 합산 후보 수(`k_global`)도 같은 규칙으로 센다.
- 판정 규칙 버전을 `medicloak-release-v9`로 올린다 (실행 기록의 `versions.medicloak_release`).
- 같은 DB 사본에서 같은 세 질문(사례마다 처방 · 시술 시기)을 고치기 전 · 뒤 코드에 물었다. 고치기 전에는 시기 값 둘을 후보 8명 · 4명으로 세어 그대로 냈고, 고친 뒤에는 이 대화 값만 센 1명 · 2명으로 보아 둘 다 가렸다. 나머지 하나(후보 2명, 가림)는 같았다. 위 배경의 대화(후보 4명으로 낸 값)도 다시 판정하면 가린다.
- 처음에는 이 대화 값을 앞에 두고 원장을 뒤에 붙여 세었다. 이 차례는 이 대화 값이 바뀔 때마다(넓힘 단계마다) 원장 묶음 보정을 처음부터 다시 해, 같은 DB 사본에서 진료 지원 AI 열기가 7.0초에서 52.6초로 늘었다. 지금 규칙은 열기 6.7초, 질문 0.3~0.5초다 (시연 모드).

### 2. 답 말투 (`textguard.natural_wording` · `tidy_gaps` · `coarsen_counts`, `live.ANSWER_STYLE`)

- 끝난 기록이 없는 처방 · 관리 계획 · 진단은 지금 이어지는 일로 쓴다 (ADR-0037 2절 첫 줄을 대신한다).
  - '1998년 12월부터 처방되어 종료 기록이 없습니다' → '1998년 12월부터 현재까지 계속 처방되고 있습니다'
  - '10회 이상 처방되었으며 종료 기록이 없습니다' → '10회 이상 처방되었으며 현재까지 이어지고 있습니다'
  - '관리 계획은 종료되지 않았습니다' → '관리 계획은 현재까지 계속 진행되고 있습니다'
  - '종료일에 도달하지 않았습니다', '아직 종료되지 않았습니다'도 같이 바꾼다. 주어가 '처방은'이면 '현재까지 이어지고 있습니다'로 써서 '처방은 … 처방되고'처럼 겹치지 않게 한다.
  - 목록의 '(종료 기록 없음)'은 '(현재까지 계속 처방 중)' · '(현재까지 진행 중)' · '(현재까지 이어짐)'으로 쓴다.
  - 처방을 복용으로 바꾸지 않는다 (기록에는 처방만 있다).
- 값을 빼고 남은 문장을 다듬는다 (`tidy_gaps`, `post_release`에서 말투 다듬기 다음): 줄 처음이나 쌍점 뒤에 홀로 남은 '시작하여'를 지우고, '사례1 환자는 거주했습니다'는 '사례1 환자의 거주 지역은 비공개입니다'로 바꾼다. 글 맨 앞의 '기록에 없음.' 꼬리표는 지우고, 그것만 남았으면 '기록에 없습니다.'로 쓴다.
- 횟수 범위: '이상 · 넘게' 같은 하한 말이 붙으면 범위 경계로 내려 한 번만 쓴다('5회 이상' → '4회 이상', '10회 넘게' → '10회 이상'). '이하 · 미만 · 이내' 상한은 9회까지만 범위 경계로 올리고 그보다 크면 그대로 둔다. 바뀌는 것이 없으면 편집으로 세지 않는다.
- 대상 AI 답 형식(`ANSWER_STYLE`, 지문 `short-v2`)에 쓸 말과 쓰지 않을 말을 함께 적는다: '현재까지 계속 처방되고 있습니다'처럼 쓰고 '종료 기록이 없습니다', '종료일에 도달하지 않았습니다'처럼 쓰지 않는다. 약 이름 옆에 용도나 질환을 괄호로 덧붙이지 않는다. 물었는데 기록에 없으면 '사례1 기록에는 처방 사유가 적혀 있지 않습니다'처럼 한 문장으로 쓴다.
- 재작성기 지시에 11번을 더한다: 값을 빼서 문장이 뜻을 잃으면 그 문장을 '사례1의 거주 지역은 비공개입니다'처럼 쓴다. 다시 고치는 안내는 12번이 된다.
- 유사 사례 보고서(ADR-0042)의 기록상 경과도 같은 말로 쓴다: '약 1~2주 만에 끝남' · '3일 이내에 끝남' · '3년 넘게 이어진 뒤 끝남', '현재까지 이어짐' · '현재까지 계속 처방 중' · '현재까지 진행 중', '처방 기간 약 3~6개월', '처음부터 마지막 시행까지 약 1~2년'. 요약 문장은 '주진단은 시작하고 약 1~2주 만에 끝났습니다', '같은 진단으로 2~3회 기록되었습니다'다.
- 차트 요약의 '종료일 없음 · 오래된 처방' 설명을 '끝난 날짜는 기록되지 않았지만, 마지막 기록이 마지막 내원보다 1년 넘게 앞서 있어 진행 중으로 보지 않았습니다'로 고친다.

### 3. 답 시간 한도 90초와 시간 초과 문장 (`medicloak/cli.py`, `review.TIMEOUT_TEXT`)

- `--answer-budget` 기본값을 45초에서 90초로 늘린다 (ADR-0032 5절의 기본값을 대신한다). 추출기 지연 중앙값 16.6초로 재작성 한 번(추출 · 재작성 · 다시 추출)이 들어갈 시간이다. 0이면 끄는 것은 같다.
- 시간을 넘긴 답의 본문은 식별 위험 거절 문장이 아니라 '답을 안전하게 확인하는 데 시간이 오래 걸려 이번 답은 보내지 않았습니다. 같은 질문을 다시 보내거나, 묻는 내용을 나눠 물어 주세요.'다. 답 아래 한 줄은 '확인하지 못한 답은 보내지 않으며, 공개한 값으로 세지 않습니다.'로 본문과 겹치지 않게 했다. 공개 방식(`REFUSAL_TIMEOUT`) · State · 원장 처리는 같다.

### 4. 화면

- '보호 담당자에게 묻기'를 오른쪽 아래 떠 있는 단추에서 진료 지원 AI 화면의 환자 줄('차트' · '내 환자' 옆)로 옮긴다 (`DeskLauncher`). 새 메시지 수를 단추에 붙이고, 보호 담당자의 새 메시지는 단추 아래에 미리 보인다. 창은 넓은 화면에서 환자 줄 바로 아래 오른쪽에 열리고, 닫으면 단추로 돌아간다. 머리줄 알림 · '답장하기' · 답 아래 안내로 여는 길은 그대로다.
- 답의 출처 표시 '기록 16'을 '16번 기록'으로 쓰고, 마우스를 올리면 '이 사례의 16번째 기록에서 나온 값입니다'가 보인다.
- 값 전체가 날짜인 값('1998' · '1998-12' · '2020-02-04' · '1947-Q4')은 답의 값 줄과 사례 노트에서 '1998년' · '1998년 12월' · '2020년 2월 4일' · '1947년 4분기'로 보인다 (`format.periodKo`, 화면에만 쓴다. 판정 · 기록의 값은 그대로다). 보고서는 이미 이렇게 쓴다.
- 시연 모드에서 질문에 답하지 않은 항목이 있으면 답 끝에 '시연 모드는 질문마다 정해 둔 항목만 답합니다. 거주지는 따로 물어 주세요.'를 붙인다 (`clinic.oracle_left`). 진단은 '진단 당시 나이'처럼 다른 항목의 기준으로 쓰이는 일이 많고 사례 목록에 늘 보이므로 세지 않는다. 실제 LLM 대화에는 붙이지 않는다.

## 근거

- 원장은 다른 대화에서 이미 나간 값을 합쳐 세려는 장치다(ADR-0032). 원장 값이 이 대화의 새 값을 밀어내면 장치가 반대로 작동한다. 값을 더한 수는 이 대화 값만 센 수보다 클 수 없어야 하므로, 보정 때문에 커졌으면 이 대화 값만 센 수를 쓴다. 이 대화 값은 지금 화면에 그대로 보이는 값이라 잡음이 적다.
- 보정 자체(`medical/grouping.py`)는 연구 하네스의 고정본이라 바꾸지 않았다. 작은 쪽 고르기는 그 앞에서 할 수 있어, 연구 결과(같은 입력이면 같은 후보 수)를 건드리지 않고 제품 판정만 보수적으로 바꾼다. 보정 결과를 기억해 두는 차례(원장 먼저)를 그대로 써서 빠르기도 같다.
- 말투는 의료진이 읽고 바로 이해하는 것을 기준으로 했다. '현재까지'는 사례 기록이 끝날 때까지 끝난 기록이 없다는 뜻이고, 팀이 예로 든 말('현재 처방이 계속되고 있다')과 같은 꼴이다.
- 시간 한도는 실행 기록의 지연 분포로 정했다. 한도를 늘려도 끝까지 확인하지 못한 답은 여전히 내보내지 않는다.

## 검토한 대안

- 보정 함수(`GroupRepairKC`) 자체를 고치기: 연구 하네스 고정본을 바꿔야 하고, 사건 묶음 보정이 필요한 다른 경우(같은 날 여러 기록)를 같이 건드린다.
- 원장 값을 판정에서 빼기: 다른 대화의 공개를 합쳐 세는 보호(ADR-0032)가 사라진다.
- 이 대화 값을 앞에 두고 원장을 뒤에 붙여 세기: 원장 값 가운데 이 대화와 맞는 것까지 살려 더 보수적이지만, 위처럼 열기가 52초까지 늘었다.
- 시간 한도를 없애기: 추출기가 응답하지 않으면 답이 끝없이 기다린다.
- 시연 모드가 여러 항목을 한꺼번에 답하게 하기: Seed 하나가 판정 단위라, 한 질문에 Seed 여럿을 쓰면 판정 · 기록 계약이 바뀐다. 남은 항목을 알려 따로 묻게 했다.
