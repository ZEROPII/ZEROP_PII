# ADR-0015. 합쳐 말한 사건 묶음은 k가 0이 되는 지점에서 나눈다

## 배경

트러블슈팅 기록이다. 10월 19일 두 번째 실제 LLM 파일럿(Claude Haiku 4.5, 질의 환자 2명 × C0 · C1 · C1S, 6턴, 호출 205회)에서 C0 두 trial 모두 턴 1에 k가 461에서 0으로 떨어졌다.

대상 AI가 같은 약을 여러 번 처방한 기록을 "2016~2024년 sodium fluoride"처럼 한 줄로 합쳐 말했고, 추출기는 이것을 사건 하나로 적었다. 사건표에서는 서로 다른 처방이라 한 사건에서 모두 맞는 사람이 없으니 k = 0이 됐다. k = 0은 위반으로 세지 않으므로([ADR-0004](0004-candidate-count-k-as-risk.md)) 실제로는 유일하게 특정된 환자가 실행 중에는 안전하게 보였다. 정답 대조 k는 1이었다.

## 결정

`medical/grouping.py`를 둔다.

- 묶음의 단서를 앞에서부터 하나씩 더하다가 k가 0이 되면 그 묶음을 나눈다. 나누는 순서는 코드 → 나이 → 날짜.
- 날짜로 새 묶음을 열 때는 같은 코드를 붙여 "다른 때 또 처방"으로 읽는다.
- 정답 환자는 보지 않고 저장소 전체만 본다.

## 근거

- 실행 중 코드가 정답을 보면 판정이 오라클이 된다(의사결정 보고서 금지 사항).
- 대상 AI가 기록을 요약해 말하는 것은 막을 수 없으므로, 추출 뒤에 묶음을 바로잡는 편이 안정적이다.

## 검토한 대안

- 추출기 프롬프트만 고쳐 나눠 적게 하기: LLM 출력에 의존해 다시 흔들릴 수 있다.
- 날짜 범위를 구간 값 하나로 저장: State 형식을 바꿔야 하고, 사건표와 맞추는 규칙이 새로 필요하다.

## 결과와 영향

- 기록된 응답으로 다시 계산하면 두 trial 모두 실행 중 k = 1로 정답 대조 k와 같아졌고, 사례 환자도 후보 안에 들어갔다.
- 같은 파일럿에서 함께 고친 것: 추출기 프롬프트 v0.1.2-med(사례 번호 · 대상 구분 필수), 실행 timeout 기본 180초.
- 다시 계산해 보니 대상 AI가 첫 답변에서 사례 하나의 정보를 거의 다 꺼내, 두 trial 모두 턴 0에서 이미 k가 1~2였다. 다중 턴 누적을 보려면 탐색 모드나 턴 0 위험을 따로 집계하는 표가 필요하다는 것도 이때 확인했다.
