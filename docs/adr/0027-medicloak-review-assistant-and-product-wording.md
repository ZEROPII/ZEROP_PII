# ADR-0027. 세부 정보 요청마다 검토 보조 에이전트가 검토 초안을 만들고, 로그인 화면과 운영 화면의 문구를 정리한다

## 배경

- **보안 담당자의 검토 부담**: 세부 정보 요청이 오면 보안 담당자는 여러 일을 혼자 한다.
  - 가린 값 목록을 연다.
  - 값마다 '그대로였다면' 후보 수를 본다.
  - 조회 목적에 필요한 값인지 판단한다.
  - 답장을 쓴다.
  - 값을 여러 개 함께 열 때의 후보 수는 화면에 없어서 따로 알 수 없었다.
  - 진료 중에 오는 요청이라 빨리 답해야 한다.
- **화면의 데모 · 시연 · 합성 데이터 문구**: 운영 화면에 아래 문구가 남아 있었다.
  - 로그인 화면 아래의 "Synthea로 만든 합성 데이터" 한 줄
  - 리포트의 'POC' 이름과 연구용 평가 대시보드 링크
  - 결정적 응답기 모드의 '데모 응답기'
  - 서버 출력의 '가상 EMR' · '[webdemo]'
- **로그인 화면**: 병원에서 실제로 쓰는 시스템처럼 보이지 않았다. 접속 기록 · 자동 로그아웃 같은 안내도 없었다.

## 결정

### 1. 검토 보조 에이전트 (`webdemo/backend/assist.py`)

의료진이 세부 정보 요청을 보내면 뒤에서 한 번 돈다. 관제 상세의 '다시 만들기'로 다시 돌릴 수도 있다. 순서는 아래와 같고, 화면에 '확인한 순서'로 그대로 보인다.

1. **요청 읽기**: 사례, 조회 목적, 의료진이 쓴 사유
2. **가린 값 모으기**: 그 사례의 공개 승인 대상 값. 값 원문은 읽지 않고 단서 종류 · 처리 · 어느 답인지만 본다.
3. **하나씩 열어 보기**: 지금 누적 상태에 그 값 하나를 더했을 때의 후보 수.
   - `Session.what_if`가 `approve`와 같은 방식으로 State 사본에 더해 센다. State는 바꾸지 않는다.
4. **조회 목적과 대조**: 처방 · 시술·치료 · 경과·관리 판단에 그 단서가 쓰이는 정도. 직접 씀 · 범위로 충분 · 관련 적음으로 나눈다(`PURPOSE_NEED`).
5. **함께 열어 보기**: 공개 가능한 값을 후보가 많이 남는 것부터 하나씩 더해 본다. 함께 열면 기준 아래로 내려가게 하는 값은 '사유 확인'으로 돌린다.
6. **초안 쓰기**: 담당자용 요약, 의료진 답장, 공개 사유를 쓴다.

추천은 규칙으로 정한다.

| 조건 | 추천 |
| --- | --- |
| 하나만 열어도 후보가 기준(5명) 이상 | 공개 가능 |
| 조회 목적과 관련 적음 | 공개하지 않음 |
| 이미 범위로 보이고, 범위로 충분한 단서 | 지금 범위 유지 |
| 열면 후보 1명 | 공개하지 않음 |
| 그 밖 (진료에 쓰이지만 기준 아래로 줄어듦) | 사유 확인 뒤 결정 |

- **LLM의 몫**: 실제 LLM은 요약과 답장 문장만 쓰고 추천은 바꾸지 않는다.
  - 모델은 재작성기와 같다(`--rewriter-model`).
  - 의료진 질문 호출이 기다리면 자리를 양보한다.
  - 사용량은 '검토 보조'로 따로 센다.
- **정해진 문장으로 돌아가는 경우**: 아래 중 하나면 LLM 대신 정해진 문장으로 쓴다.
  - 결정적 응답기 · 연결 점검 모드
  - 호출 실패
  - LLM 답이 JSON 형식이 아님
  - 의료진 답장에 숫자('사례 N' 제외)나 '후보'가 섞임
- **LLM에 보내지 않는 것**: 가린 값의 원문, 환자 번호, 과거 기록. 보내는 것은 단서 종류 · 처리 · 후보 수 · 조회 목적 · 요청 문장뿐이다.
- **스스로 하지 않는 일**: 공개 · 답장 · 규칙을 보내지 않는다. 관제 상세에서 담당자가 직접 한다.
  - '공개 가능 N개를 승인 창에 담기': 공개 승인 창에 고를 값과 사유 초안을 채운다.
  - '답장 칸에 넣기': 답장 칸에 초안을 넣는다.
- **기록과 API**:
  - 초안은 메모리에만 둔다.
  - 만들 때마다 감사 기록 `assist_draft`를 남긴다(행위자 '검토 보조 AI'). 사례 · 추천 · 추천별 수 · 쓴 방식만 담고 값은 담지 않는다.
  - API: `GET · POST /api/monitor/sessions/{대화}/assist` (보안 담당자 전용).
- **화면**: 관제 상세의 스크롤 영역 맨 앞에 검토 보조와 공개 승인 창을 둔다. 내용이 길어도 승인 단추까지 내려갈 수 있다.

### 2. 로그인 화면

- 왼쪽은 EMR 머리줄과 같은 짙은 청록 판이다. 제품 이름, 한 줄 설명, 역할 둘을 둔다.
- '과거 진료 기록' 표는 값 없이 막대 모양만 그린다. 답이 나가기 전 값마다 하는 세 가지 처리(그대로 · 범위로 바꿈 · 비공개)를 보인다. 실제 기록이나 예시 값은 넣지 않는다.
- 오른쪽 로그인 양식에는 다음을 둔다.
  - 비밀번호 보기
  - Caps Lock 알림
  - 사실인 안내 셋: 감사 기록, 60분 미사용 시 자동 로그아웃(`auth.IDLE_TIMEOUT`), 계정 문의처
- 아래에 판정 규칙 판(`/api/health`의 `release`)을 보인다.
- 합성 데이터 안내 줄은 지운다. 데이터 출처는 README와 논문에 적는다.

### 3. 운영 화면 · 서버 출력 문구

- 리포트: 'POC'를 '기준 평가'로 바꾼다. 연구용 평가 대시보드(`eval_demo/`) 링크는 운영 서버에서 숨긴다(경로는 남김).
- 결정적 응답기 모드의 대상 AI 이름은 '결정적 응답기'로 한다. 이해하지 못한 질문의 안내는 '이 진료 지원 AI는…'으로 쓴다.
- 의료진 환경의 위치 이름은 'MediCloak 외래 진료 지원'으로 한다. FHIR 메타데이터의 소프트웨어 이름은 'MediCloak EMR 연동 (FHIR R4)'로 한다.
- 서버 출력은 'EMR 적재', '[medicloak]'으로 한다. `--llm dry-run`은 '연결 점검 모드'로 부른다.
- 확인: 로그인 전 · 의료진(외래 목록 · 환자 열기 · 질문 · 세부 정보 요청) · 보안 담당자(관제 · 승인 창 · 의료진 대화 · 리포트 · 감사 기록 · 정책 · 용어 · 안내) 화면의 보이는 글자, title · aria-label · placeholder를 훑는다. 데모 · 시연 · 개발 · 테스트 · 가상 · 합성 · Synthea · POC · 가짜 · 연구 · 실험 · dry-run 같은 말이 없다.
- `python -m webdemo`(LLM 없는 연구 재현 모드)의 문구는 그 모드 설명이라 그대로 둔다.

## 근거

- **검토 보조의 쓸모**: 검토의 대부분은 숫자를 세고 표에 맞춰 보는 일이라 규칙으로 정확하게 할 수 있다. 판단이 필요한 것은 공개 여부와 사유다.
  - 그래서 계산 · 추천은 규칙으로 하고, 결정은 사람이 한다.
  - LLM은 사람이 읽고 보낼 글을 다듬는 데만 쓴다.
  - '함께 열어 보기'는 지금 화면에 없던 정보다. 하나씩은 괜찮아도 둘을 함께 열면 기준 아래로 내려가는 경우를 잡는다.
- **LLM에 값을 보내지 않는 이유**: 원문 없이도 판단에 필요한 것이 다 있다. 보안 담당자 도구가 새로운 유출 경로가 되지 않게 한다.
- **로그인 화면**: 병원 시스템의 로그인 화면은 누가 무엇을 하는 시스템인지와 사용 규칙을 알리는 곳이다. 제품을 설명하는 그림은 값을 쓰지 않아도 처리 방식을 보일 수 있다.

## 검토한 대안

- **LLM이 추천까지 정하기**: 같은 요청에 다른 추천이 나올 수 있고, 근거를 숫자로 되짚기 어렵다. 쓰지 않는다.
- **자동 승인(공개 가능이면 바로 공개)**: 공개는 되돌릴 수 없다. 사람이 고르게 둔다.
- **도구를 고르는 에이전트 루프(LLM이 what_if를 골라 부름)**: 지금 판단에 필요한 계산은 정해진 여섯 단계로 충분하다. 호출 수 · 지연 · 재현성이 나빠지므로 쓰지 않는다.
- **로그인 화면에 예시 진료 기록 넣기**: 실제 기록처럼 보이는 값은 넣지 않는다. 막대 모양으로만 처리 방식을 보인다.

## 결과와 영향

- 세부 정보 요청 하나에 실제 LLM 호출이 1번 늘어난다. 모델은 재작성기 모델을 쓴다.
- 감사 기록에 `assist_draft`가 더해진다. 데모 서버 테스트는 이 기록을 순서 비교에서 뺀다.
- `/api/health`에 `release`가 더해진다.
- 테스트
  - 초안 만들기(판정 · 순서 · LLM 프롬프트에 값 없음 · 아무것도 보내지 않음 · 감사 기록 · 의료진 403)
  - 정해진 문장으로 돌아가기(답장에 숫자 · JSON 아님), 다시 만들기
  - 함께 열어 보기(하나씩은 기준 이상, 함께면 아래), 조사 · 나열
  - `what_if`가 State를 바꾸지 않음

## 남은 일

- `PURPOSE_NEED` 표는 병원 진료과와 정한다(지금은 처방 · 시술·치료 · 경과·관리 기본값).
- 공개 승인의 만료 · 철회(ADR-0026에서 이어짐).
- 검토 초안을 DB에 남길지 정한다. 지금은 메모리에만 두고, 감사 기록에는 요약만 남긴다.
