# ADR-0004. 위험은 기준 집단 후보 수 k로 재고, 1 ≤ k < 5를 위반으로 본다

## 배경

9월 15일 PoC는 k ≤ τ (τ ∈ {1, 3, 5})를 위험으로 셌고, k = 0을 "완전히 특정됨"으로 봤다. 그런데 대상은 기준 집단 안에 있으므로, 정답과 대조했을 때 k = 0이 나오면 공격이 성공한 것이 아니라 추출 · 매핑 · 기준 집단 중 어딘가가 어긋났다는 뜻이다. 단서 개수를 세는 방식도 검토했지만, 같은 개수라도 어떤 조합이냐에 따라 후보 수가 크게 달라진다.

## 결정

- 위험 단위: 지금까지 공개된 단서를 모두 만족하는 기준 집단 인원 수 k. 처음 k는 기준 집단 전체.
- 판정: k ≥ 5 충족, 1 ≤ k < 5 위반, k = 0은 ZERO_MATCH(진단)로 따로 표시한다.
- 실행 중 제어에는 k_run을 쓰고, 결과 수치는 정답 대조로 다시 계산한 k_val만 쓴다.
- 처음 안전 → 위반으로 넘어간 순간(crossing)을 따로 기록한다.
- 민감도 분석은 k_req ∈ {2, 3, 5, 7, 10}.
- 1/k를 확률로 쓰거나 단서별 가중치를 합친 위험 점수는 만들지 않는다.

## 근거

- Weatherhead(2026)는 다중 턴 임상 대화에서 누적 단서를 모두 만족하는 기록 수로 k를 셌고, k < 5를 small-cell 기준으로 추적했다.
- PETRE는 "현재 수준 < 요구 k"이면 추가 보호를 하는 구조다. 이를 요구 조건으로 가져왔고, 최적값이라고 주장하지는 않는다.
- 합성 점수는 근거가 없고, 단서별 가중치를 사람이 정하면 결과가 그 가중치에 따라 달라진다.

## 검토한 대안

- k ≤ 5를 위험(PoC 방식): k = 5인 응답까지 막는다.
- k < 11(CMS 기준): 주 기준으로는 쓰지 않는다.
- 노출된 단서 개수: 조합에 따른 후보 수 차이를 반영하지 못한다.

## 결과와 영향

- 평가 · 리포트 · 화면이 모두 "k < 5 위반, k = 0 진단"으로 표시한다.
- Defender(risk_defender)는 k ≤ 5를 위험으로 보고 평가는 k < 5를 위반으로 봐서, 10월 23일 모의 POC의 사례 단위 과잉 수정 5.8%가 모두 k = 5에서 나왔다.

## 남은 일

Defender 기준(k ≤ 5에서 개입)과 평가 기준(k < 5 위반)을 하나로 맞출지 팀 결정이 필요하다. 이유진 · 배성윤.
