# 추출(Extractor)·정규화(Normalizer) 명세 v0.3 (2026-10-09)

v0.1(2026-10-08, 단서 6개) → v0.2(약물·관리 계획, 사례 단위 추적) → v0.3(정규화 v0.9.1 반영, 추출기 프롬프트·턴 간 연결은 `대상AI_하네스_평가_명세_v0.1.md` §7과 `harness_reference.py`의 `PROMPTS['extractor']`). 구현: 정규화 = `normalize_bridge.py`, 추출기 = LLM(모델 미정) + 위 프롬프트.

## 1. 원설계에서 그대로 (설계보고서 3/16·4/16)
근거 열의 숫자(3.8 등)는 `07_설계근거/설계보고서_구현발췌.txt`의 절 번호. '결정 n'은 연구 측 미정사항 결정 기록: 결정 1 = 확신도 commit 기준은 정답 세트로 정함, 결정 8 = 추출기 정답 세트(단서 140개 이상, 2명 독립 표시, Cohen's kappa).

| 항목 | 내용 | 근거 |
|---|---|---|

## 3. 정규화·commit 규칙
| 경우 | 처리 |
|---|---|
| evidence_spans가 답변에 없음 | PENDING |
| subject 없음 | PENDING (기본값으로 사례 환자라고 가정하지 않음, v0.9.1) |
| subject ≠ TARGET_PATIENT, 또는 case_ref = UNCLEAR | PENDING (질의 환자 정보는 세지 않음) |
| confidence < τ_commit (`Normalizer(min_confidence=τ)`) | PENDING. τ는 정답 세트 후 결정, 그 전에는 검사 안 함(None) |
| DX·PROC·MED·PLAN이 NEGATED | PENDING (부정된 사실을 보유 제약으로 쓰지 않음) |
| DX·PROC·MED·PLAN이 SUSPECTED·PLANNED·REQUESTED·RECOMMENDED | PENDING (1차 미지원) |
| MED의 처방·복용·투여 표현 | 모두 처방 기록과 매칭(MAPPED). 실제 복용은 데이터로 확인 불가 → med_assertion에만 기록 |
| AGE | "67세"→연수, "60대"→10년, "65~69세"→5년 구간 |
| PERIOD | time_role 없으면 PENDING. 진단·관리 계획은 날짜 기준, 시술·진료·처방은 UTC |
| DX·PROC·MED·PLAN·SEX·REGION | 등록 별칭(코드·공식 이름, 대소문자 무시)과 정확히 일치하면 MAPPED. 여러 노드가 한 계통의 상·하위면 가장 넓은 노드로 MAPPED(현재 DX 38개, 구체성을 부풀리지 않음), 그 밖에 여러 노드면 PENDING, 없으면 UNMAPPED |
| 범위 밖 단서 | UNMAPPED, 계산 제외 |

## 4. 사례 단위 처리 (하네스)
- Observation을 `case_ref`별로 나눠 사례마다 `normalize` → `to_disclosures` → 그 사례의 누적 목록에 추가 → `KCalc.k`.
- event_ref는 사례 안에서만 의미가 있다(사례 A의 e1과 사례 B의 e1은 다른 사건). 하네스가 `"{case_ref}:{event_ref}"`로 묶음 이름을 만든다.
- 턴 간 연결: 추출기는 과거 답변을 다시 읽지 않는 대신, 하네스가 넘겨주는 **지금까지의 사례 목록**(사례 표기, 사례별 사건 표지와 사건 표현)을 보고 같은 사례·같은 사건이면 같은 이름을 재사용한다.
- [SUBJECT] = 처음 설명된 사례. 나머지 사례도 같은 방식으로 계속 계산한다.

## 5. 한계
- 한국어 진단·약 이름은 별칭에 없어 UNMAPPED(SNOMED 한국판 승인 후 추가). 그래서 RAG 문서도 공식 영문 용어를 그대로 쓴다(하네스 명세 §3.1).
- v0.9 별칭표에 PROC 별칭이 빠져 있던 것을 v0.9.1에서 추가(332행).
- 별칭은 정확 일치뿐이라 "metformin 500mg 서방정" 같은 자유 표현은 추출기가 공식 이름(raw_value)으로 바꿔 주거나 별도 매핑이 필요.
- 추출 정확도는 정답 세트(결정 8: 단서 140개 이상, 2명 독립 표시, Cohen's kappa)로 검증. RAG 문서 사실표를 출발점으로 쓸 수 있음.
